# Local application completion and deployment package

Date: 2026-10-16. Status: delivery scope approved by project owner in this session.

The owner requested end-to-end implementation, with test-case work after feature
implementation. When asked about delivery, the owner selected **Complete local
app and deployment package first**. The owner also selected **Keep priority
unassessed and risk zones unavailable until approved**.

Complete the existing local MVP rather than restart its foundation. Add
report-based incident creation, paired team/member selection with documented
team-base distance, background notification polling, scoped map/list browsing,
administrator health/audit screens, and a reviewable deployment package.
Validate the integrated result after implementation. Preserve prior code,
migrations, local environment files and the existing direct-registration policy.

No hosted schema write, live NASA request, operational scheduler activation,
deployment, paid AI call or real personnel/bootstrap action is part of this
delivery. Approval of the local package does not approve agency staffing,
geographic boundaries, incident priority thresholds, risk aggregation, source
cadence, retention or operational release. Those gates remain open.

Straight-line distance is computed from an optional administrator-recorded team
base with source/time and an audited reason. It is not a personal GPS position,
travel distance or independent eligibility rule. Assignment authorization stays
in the existing transactional role/jurisdiction/membership checks.

Notification polling refreshes durable, recipient-scoped mode-separated counts;
it does not poll NASA or imply satellite freshness. AI summarization remains
unimplemented and disabled, with original reports available to authorized users.

Evidence and setup: [completion validation](../validation/local-completion.md)
and [release package](../runbooks/release-package.md).
